## 🔥 项目推荐（按面试加分程度排序）

### 1. 分布式任务调度系统 ⭐⭐⭐⭐⭐

**项目简介：**
类似 xxl-job 或 Airflow，用 Go 实现的分布式任务调度平台

**核心功能：**
- 定时任务管理（支持 cron 表达式）
- 任务分片执行（多节点负载均衡）
- 任务失败重试和告警
- 执行日志和监控
- 动态任务注册和配置
- 任务依赖管理（DAG）
- 执行器管理（注册、心跳、下线）

**技术亮点：**
- **分布式锁**：Redis/Etcd 实现，防止任务重复执行
- **一致性哈希**：任务分片算法，保证负载均衡
- **Goroutine Pool**：并发控制，防止资源耗尽
- **gRPC**：节点间通信，任务下发和结果回传
- **WebSocket**：实时日志推送
- **时间轮算法**：高效的定时任务触发
- **Raft 协议**：调度中心高可用（可选）

**数据库设计：**
```
- job_info（任务配置表）
- job_log（执行日志表）
- job_lock（分布式锁表）
- executor（执行器注册表）
```

**面试话术：**
"我实现了一个分布式任务调度系统，解决了多节点任务重复执行的问题。用 Redis 实现分布式锁保证任务唯一性，用一致性哈希做任务分片实现负载均衡，支持百万级任务调度。还实现了失败重试、执行日志、实时监控等功能。"

**可以深入讨论的点：**
- 分布式锁的实现细节（RedLock 算法）
- 任务分片算法（一致性哈希 vs 取模）
- 如何保证任务不丢失（持久化 + ACK 机制）
- 如何处理执行器宕机（心跳检测 + 任务重新分配）
- 如何优化大量定时任务的触发性能（时间轮）

### 2. API 网关 + 限流熔断系统 ⭐⭐⭐⭐⭐

**项目简介：**
类似 Kong/APISIX 的轻量级 API 网关

**核心功能：**
- 动态路由转发（支持路径、Header、Query 匹配）
- 限流（令牌桶/漏桶/滑动窗口算法）
- 熔断降级（Hystrix 模式）
- 认证鉴权（JWT/OAuth2/API Key）
- 请求日志和链路追踪
- 插件系统（中间件动态加载）
- 负载均衡（轮询/随机/加权/最小连接）
- 灰度发布（按比例/按用户）

**技术亮点：**
- **高性能反向代理**：基于 fasthttp 或原生 net/http
- **滑动窗口限流**：Redis + Lua 脚本实现
- **熔断器状态机**：关闭 -> 打开 -> 半开
- **插件化架构**：责任链模式 + 反射动态加载
- **Prometheus 监控**：QPS、延迟、错误率
- **配置热更新**：Etcd/Consul watch 机制

**核心算法：**
```go
// 令牌桶限流
type TokenBucket struct {
    capacity  int64  // 桶容量
    tokens    int64  // 当前令牌数
    rate      int64  // 令牌生成速率
    lastTime  time.Time
}

// 熔断器状态机
type CircuitBreaker struct {
    state         State  // Closed/Open/HalfOpen
    failureCount  int
    successCount  int
    threshold     int
    timeout       time.Duration
}
```

**面试话术：**
"我实现了一个高性能 API 网关，用令牌桶算法做限流，QPS 可以达到 10w+。支持动态配置路由，实现了熔断降级保护后端服务。还做了插件化架构，可以动态加载中间件，支持灰度发布和链路追踪。"

**可以深入讨论的点：**
- 限流算法对比（令牌桶 vs 漏桶 vs 滑动窗口）
- 熔断器如何判断服务恢复（半开状态的设计）
- 如何实现高性能（零拷贝、连接池、协程池）
- 插件系统的设计（如何保证插件隔离和安全）
- 灰度发布的实现（如何保证流量准确切分）

### 3. 实时消息推送系统 ⭐⭐⭐⭐⭐

**项目简介：**
类似企业微信/钉钉的实时消息系统

**核心功能：**
- WebSocket 长连接管理
- 单聊/群聊/系统通知
- 消息可靠投递（ACK 机制）
- 离线消息存储和推送
- 消息已读/未读状态
- 在线状态同步
- 消息撤回和编辑
- 文件传输（图片、视频、文件）

**技术亮点：**
- **百万级连接管理**：epoll + Goroutine per connection
- **消息队列**：Kafka 做消息中转，保证可靠投递
- **分布式 Session**：Redis 存储用户连接信息
- **心跳保活机制**：客户端定时 ping，服务端超时断开
- **消息分片存储**：按用户 ID 分库分表
- **推拉结合**：在线推送 + 离线拉取
- **负载均衡**：一致性哈希分配连接到不同节点

**架构设计：**
```
Client -> WebSocket Gateway -> Message Queue -> Message Service -> DB/Cache
                ↓
          Connection Manager (Redis)
```

**面试话术：**
"我实现了一个实时消息推送系统，单机支持 10w+ WebSocket 长连接。用 Kafka 做消息队列保证可靠投递，用 Redis 做在线状态同步和分布式 Session 管理。实现了消息 ACK 机制、离线消息存储、群聊等功能。"

**可以深入讨论的点：**
- 如何支持百万级连接（epoll、连接复用、内存优化）
- 消息可靠投递如何保证（ACK、重试、幂等）
- 群聊消息如何高效推送（扇出写 vs 扇出读）
- 如何处理连接断开和重连（Session 恢复、消息补偿）
- 如何做水平扩展（连接迁移、消息路由）

### 4. 短链接服务 ⭐⭐⭐⭐

**项目简介：**
类似 bit.ly 的短链接生成和跳转服务

**核心功能：**
- 长链接转短链接（Base62 编码）
- 短链接跳转（302 重定向）
- 访问统计（UV/PV/地域/设备）
- 自定义短链接（个性化域名）
- 过期时间设置
- 防刷机制（IP 限流、验证码）
- 链接黑名单（恶意链接过滤）

**技术亮点：**
- **分布式 ID 生成**：Snowflake 算法，保证全局唯一
- **Base62 编码**：数字 ID 转短字符串
- **布隆过滤器**：快速判断短链接是否存在
- **Redis 缓存**：热点短链接缓存，减少 DB 查询
- **限流防刷**：令牌桶 + IP 黑名单
- **高并发优化**：读写分离、缓存预热、异步统计

**核心算法：**
```go
// Snowflake ID 生成
type Snowflake struct {
    timestamp    int64  // 41 bits
    datacenterID int64  // 5 bits
    workerID     int64  // 5 bits
    sequence     int64  // 12 bits
}

// Base62 编码
func Base62Encode(num int64) string {
    chars := "0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ"
    // 实现编码逻辑
}
```

**面试话术：**
"我实现了一个高性能短链接服务，用 Snowflake 算法生成分布式 ID，用 Base62 编码生成短链接。用布隆过滤器防止重复，用 Redis 缓存热点数据，QPS 可以达到 5w+。还做了访问统计、防刷机制和链接黑名单功能。"

**可以深入讨论的点：**
- 如何保证短链接全局唯一（Snowflake vs UUID vs 数据库自增）
- 如何处理短链接冲突（重试 vs 预生成）
- 如何优化跳转性能（缓存策略、CDN）
- 如何做访问统计（实时 vs 异步、精确 vs 近似）
- 如何防止恶意刷量（限流、验证码、风控）

### 5. 对象存储服务 ⭐⭐⭐⭐

**项目简介：**
类似 MinIO/OSS 的对象存储服务

**核心功能：**
- 文件上传/下载（支持大文件）
- 分片上传（Multipart Upload）
- 断点续传
- 秒传（文件去重）
- 图片处理（压缩、裁剪、水印、格式转换）
- 视频处理（转码、截图、水印）
- CDN 加速
- 权限控制（公开/私有/签名访问）

**技术亮点：**
- **文件 MD5 去重**：相同文件只存一份
- **分片并发上传**：提高大文件上传速度
- **流式处理**：不占用内存，边读边写
- **图片处理**：Go image 库 + imagick
- **分布式存储**：多副本、纠删码
- **对象元数据**：存储文件信息、访问权限

**架构设计：**
```
Client -> API Gateway -> Upload Service -> Storage Engine
                              ↓
                        Metadata DB (MySQL)
                              ↓
                        File Storage (Local/S3/OSS)
```

**面试话术：**
"我实现了一个对象存储服务，支持分片上传和断点续传，用 MD5 实现秒传功能。还做了图片处理功能，支持动态裁剪、压缩和水印。用流式处理优化内存占用，支持大文件上传。"

**可以深入讨论的点：**
- 分片上传如何实现（分片大小、并发控制、合并策略）
- 秒传如何实现（MD5 计算、引用计数、垃圾回收）
- 图片处理如何优化（缓存、异步处理、CDN）
- 如何保证数据可靠性（多副本、纠删码、校验和）
- 如何做权限控制（签名 URL、ACL、Bucket Policy）

### 6. 分布式配置中心 ⭐⭐⭐⭐

**项目简介：**
类似 Apollo/Nacos 的配置管理平台

**核心功能：**
- 配置管理（增删改查）
- 配置版本管理（历史版本、回滚）
- 配置实时推送（长轮询/WebSocket）
- 灰度发布（按实例、按比例）
- 配置继承（环境继承、集群继承）
- 权限管理（操作审计）
- 配置加密（敏感信息）
- 多环境隔离（dev/test/prod）

**技术亮点：**
- **长轮询**：客户端 hold 请求，配置变更时立即返回
- **观察者模式**：配置变更通知所有订阅者
- **配置加密**：AES 加密存储敏感配置
- **灰度发布**：按实例 IP、按百分比灰度
- **配置审计**：记录所有操作日志
- **高可用**：主备切换、数据同步

**核心流程：**
```
1. 客户端启动 -> 拉取配置 -> 缓存本地
2. 客户端长轮询 -> 服务端 hold 请求
3. 配置变更 -> 通知所有长轮询客户端
4. 客户端收到通知 -> 拉取最新配置 -> 回调业务
```

**面试话术：**
"我实现了一个分布式配置中心，用长轮询实现配置实时推送，支持配置版本管理和灰度发布。还做了配置加密、权限管理、操作审计等功能。客户端支持本地缓存和配置热更新。"

**可以深入讨论的点：**
- 长轮询 vs WebSocket vs SSE（优缺点对比）
- 如何保证配置推送的可靠性（重试、ACK）
- 灰度发布如何实现（实例选择、流量切分）
- 如何处理配置冲突（版本号、乐观锁）
- 如何做高可用（主备、数据同步、故障切换）

### 7. 秒杀系统 ⭐⭐⭐⭐⭐

**项目简介：**
电商高并发秒杀场景

**核心功能：**
- 商品秒杀（限时抢购）
- 库存扣减（防超卖）
- 订单创建
- 支付流程
- 限流防刷（IP/用户维度）
- 排队机制（虚拟队列）
- 风控系统（黄牛识别）

**技术亮点：**
- **Redis 预减库存**：减少 DB 压力
- **Lua 脚本**：保证库存扣减原子性
- **消息队列异步下单**：削峰填谷
- **令牌桶限流**：防止流量冲击
- **分布式锁**：防止超卖
- **缓存预热**：提前加载热点数据
- **页面静态化**：CDN 加速

**核心流程：**
```
1. 用户点击秒杀 -> 限流检查 -> 风控检查
2. Redis 预减库存（Lua 脚本）
3. 发送 MQ 消息（异步下单）
4. 消费 MQ -> 创建订单 -> 扣减 DB 库存
5. 返回结果 -> 用户支付
```

**核心代码：**
```lua
-- Redis Lua 脚本（原子性扣减库存）
local stock = redis.call('get', KEYS[1])
if tonumber(stock) > 0 then
    redis.call('decr', KEYS[1])
    return 1
else
    return 0
end
```

**面试话术：**
"我实现了一个秒杀系统，用 Redis + Lua 脚本防止超卖，用消息队列削峰，支持 10w+ QPS。还做了限流、防刷、风控等机制。用缓存预热和页面静态化优化性能。"

**可以深入讨论的点：**
- 如何防止超卖（Redis 原子操作、分布式锁、乐观锁）
- 如何削峰（消息队列、排队机制、限流）
- 如何防止黄牛（风控规则、验证码、实名认证）
- 如何优化性能（缓存、静态化、CDN、读写分离）
- 如何保证数据一致性（Redis 和 DB 的一致性）
